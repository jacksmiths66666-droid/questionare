## 数据清洗流程

### 第一阶段：信号筛选（01_screen.py）

对每行计算 4 类独立信号，统计 signal_count = 0 / 1 / 2+：

| 信号 | 规则 | 说明 |
|:----|:-----|:-----|
| A 长字符串 | 任一答案连续相同字符 ≥ 13 | straightlining / 乱敲 |
| B 奇偶过低 | 奇偶字符分布显著偏离随机 | 乱打键盘特征 |
| C 异常值 | Mahalanobis 距离超出阈值 | 多维特征偏离群体 |
| D 一票否决 | 开放题纯乱码或全量表缺失 | 直接判无效，不进复核 |

| 指标 | 数量 | 说明 |
|:----|-----:|:-----|
| 原始数据 | 71,922 | 71,922 条 × 68 国 |
| 无信号（NORMAL） | 54,913 | 乱码检测通过则判有效（77 行乱码独立直判无效） |
| 触发 1 个信号（MEDIUM） | 16,673 | 进入复核队列 |
| 触发 ≥2 个信号（HIGH） | 160 | 进入复核队列 |
| IDN/PRT 降级（VERIFY） | 176 | 进入复核队列 |
| 一票否决（乱码） | 77 | 直接判无效（信号筛选阶段 45 长乱码 + 最终生成阶段 32 短乱码补充检测） |

复核队列合计：17,009 行。

## 规则收紧记录（重要）

早期版本曾采用：
- 规则 A：开放题合计 ≤5 字符 → invalid（**已删除**，对 CJK 语言固有偏差）
- 规则 B：ls_max_run ≥ 17 → invalid（**改为 ≥ 13**，数据驱动收紧）

最终规则（2026-07-30 起）：
- 长字符串阈值：ls_max_run ≥ 13
- MEDIUM 层长字符串行（15,856）全部判无效（straightlining 直接证据）
- MEDIUM 非长串行（817）经内容审核：729 valid + 88 invalid

目标有效率 70-80%，实际 **77.68%**，符合预期。

## 乱码检测修正记录

### 原检测逻辑问题

1. 熵阈值过于激进：短文本自然低熵被误杀
2. 编码乱码误判：高位字符占比 >0.3 误杀西里尔/希腊/CJK 文字
3. 符号占比门槛过低：正常标点被误判

### 修正方案

| 指标 | 旧逻辑 | 新逻辑 |
|:----|:-------|:-------|
| E（熵） | raw_entropy < 5% 分位数 | adjusted_entropy < 0.3 & raw < 2.0 |
| S（符号） | symbol_ratio > 0.5 & n≥3 | symbol_ratio > 0.7 & n≥5 |
| D（数字） | digit_ratio > 0.8 & n≥5 | 不变 |
| M（编码） | high_count/len > 0.3 | U+FFFD \| control > 0.3 \| surrogates |

### 修正效果

| 指标 | 修正前 | 修正后 |
|:----|-------:|-------:|
| 一票否决数 | 13,816 | 45 |
| 误报数 | ~13,416 | 0 |
| 有效数据率 | 80.8% | 99.94%（修正后进一步收紧至 77.68%） |

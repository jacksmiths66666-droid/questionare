## 乱码检测修正记录

### 原检测逻辑问题

原检测 `is_gibberish()` 函数存在三个误报来源：

1. **熵阈值过于激进**：使用数据驱动的 5% 分位数作为阈值，导致短文本（<20字符）自然低熵被误杀
2. **编码乱码误判**：将高位字符（ord > 0x00FF）占比 > 0.3 视为编码乱码，导致西里尔/希腊/CJK 等非拉丁文字被错误标记
3. **符号占比门槛过低**：原门槛 0.5 过低，正常文本中的标点符号可能被误判

### 修正方案

| 指标 | 旧逻辑 | 新逻辑 | 修正原因 |
|:----|:-------|:-------|:---------|
| E（熵） | raw_entropy < 5%分位数 | adjusted_entropy < 0.3 & raw_entropy < 2.0 | 短文本自然低熵 |
| S（符号） | symbol_ratio > 0.5 & n≥3 | symbol_ratio > 0.7 & n≥5 | 门槛过低 |
| D（数字） | digit_ratio > 0.8 & n≥5 | 不变 | 原逻辑正确 |
| M（编码） | high_count/len > 0.3 | U+FFFD \| control_chars > 0.3 \| surrogates | 非拉丁文字误判 |

### 修正效果

| 指标 | 修正前 | 修正后 |
|:----|-------:|-------:|
| 一票否决数 | 13,816 | 45 |
| 误报数 | ~13,416 | 0 |
| 真乱码数 | ~400 | 45 |
| 有效数据率 | 80.8% | 99.94% |

## 第三阶段：两规则收紧（06_tighten_rules.py）

在完成上述修复后有效率达 99.09%，为提升分析质量，按两规则进一步收紧。

### 规则

| 规则 | 条件 | 说明 |
|:----|:-----|:-----|
| A（开放题质量） | BENEFIT_OPEN + TRUST_OPEN 合计 ≤5 字符 | 开放题填写过短，无分析价值 |
| B（同选检测激进） | ls_max_run ≥ 17 | 大规模连续同选，明显随意作答 |

### 执行效果

| 指标 | 值 |
|:----|---:|
| 目标有效率 | 80-90% |
| 实际有效率 | 89.47% |
| 新增 invalid | 6,918 |
| 规则 A 单独命中 | 3,470 |
| 规则 B 单独命中 | 3,085 |
| 规则 A+B 同时命中 | 363 |
| 规则 B 命中中开放题合计>5字 | 3,448（规则 B 不依赖开放题长度） |

### 各国差异

规则 A 对 CJK 语言剔除率较高（字符数阈值固有偏差）：
- TWN: 30.0%, HKG: 26.2%, CHN: 10.4%
- 英文国家：USA 2.2%, GBR 1.0%

详见 `tightening_evidence.md`
